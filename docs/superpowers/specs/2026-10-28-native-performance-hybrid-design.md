# yzip 네이티브 성능 가속 혼합 설계

## 의도

yzip의 강점인 다중 스레드 7z 압축은 유지하면서, 반디집보다 크게 느린 ZIP·7z 해제와 고스레드 ZIP 압축을 네이티브 경로로 가속한다. 속도를 위해 무결성, 경로 안전성, 취소, 기존 파일 보존을 약화하지 않는다.

## 측정 기준

- 같은 PC, NVMe, 원본 데이터, 압축 레벨, 요청 스레드 수에서 `bz.exe -t:N`과 yzip을 비교한다.
- 프로세스 시작 시간을 포함한 사용자 체감 wall time과 엔진 실행 시간을 별도로 기록한다.
- 각 조건은 워밍업 후 최소 7회 실행하고 중앙값·p95·출력 크기·최대 메모리·CPU 시간을 기록한다.
- 데이터는 대형 텍스트, 비압축성 데이터, 1,500개 이상 소파일, 실제 혼합 프로젝트, 단일 대형 파일로 구성한다.
- 모든 결과는 상대 프로그램으로 교차 해제하고 SHA-256 트리를 비교한다.
- 우선 성공 기준은 ZIP 압축·ZIP 해제·7z 해제의 핵심 조건 중앙값이 반디집의 110% 이내, 기존 대비 최소 2배가 가능한 조건은 50% 이하로 단축하는 것이다.
- 합격 판정의 핵심 조건은 레벨 5·8스레드에서 대형 텍스트, 비압축성 데이터, 1,500개 소파일, 실제 혼합 프로젝트, 단일 대형 파일의 ZIP 압축·ZIP 해제·7z 해제다. 1·4·16스레드는 회귀와 확장성 판단 자료로 사용한다.
- 이미 우세한 8스레드 이상 7z 압축은 현재 중앙값 대비 5% 넘게 느려지면 실패다.
- 특정 포맷 구조상 목표에 미달하면 수치와 병목을 그대로 보고하며 결과를 과장하지 않는다.

## 범위

### 포함

- 암호화되지 않은 ZIP Store/Deflate 압축·해제 네이티브 가속
- 일반 7z LZMA/LZMA2 해제 네이티브 가속
- ZIP AES, 특수 메서드, 지원하지 않는 7z coder의 안전한 기존 경로 fallback
- GUI/CLI의 진행률·취소·덮어쓰기 정책 유지
- x64 Windows 배포판과 GitHub Actions 빌드
- 동일 스레드·동일 데이터 벤치마크 자동화

### 제외

- 이미 빠른 자체 7z 압축 엔진 교체
- 외부 `7z.exe` 또는 반디집 실행 파일 호출
- RAR·EGG·ALZ 등 이번 성능 목표 밖 포맷 재구현
- 압축률을 크게 낮춰 속도만 맞추는 비교
- 코드 서명

## 선택한 접근

### 검토한 대안

1. Python 미세 최적화만 적용: 배포 위험은 작지만 단일 ZIP 스트림 해제와 py7zr fallback의 구조적 격차를 제거할 수 없다.
2. ZIP·7z 전체를 네이티브 엔진으로 교체: 장기적으로 단순하지만 이미 우세한 7z 압축과 AES·편집 호환성까지 한 번에 위험에 노출한다.
3. 혼합 네이티브 가속: 느린 경로만 네이티브로 전환하고 기존 엔진을 fallback 및 기준 구현으로 유지한다.

3번을 선택한다. 성능 이득이 입증된 경로만 단계적으로 기본값으로 승격한다.

## 네이티브 구조

### 엔진

- 공식 7-Zip `7z.dll` 26.05 계열의 DLL 인터페이스를 사용하는 얇은 C++ 브리지 `yzip_accel.dll`을 추가한다.
- 외부 프로세스는 실행하지 않는다. 현재 배포에 포함된 `7z.dll`을 프로세스 내부에서 동적 로드한다.
- 공식 `Client7z` 예제를 기준으로 필요한 `IInArchive`, `IOutArchive`, stream/callback 인터페이스만 구현한다.
- 7-Zip ABI와 DLL 버전을 시작 시 검증한다. 불일치·로드 실패·미지원 기능은 오류가 아니라 기존 Python 엔진 fallback 사유로 처리한다.
- 브리지는 GUI 프로세스 내부에서 동작한다. 별도 helper EXE는 만들지 않는다. 접근 위반 같은 네이티브 프로세스 충돌은 현재 작업 복구 대상이 아니며, 공식 고정 DLL·좁은 인터페이스·악성 입력 테스트로 발생 가능성을 낮춘다.
- 브리지는 파일 경로나 임의 추출을 직접 결정하지 않는다. Python이 검증한 작업 목록과 임시 출력 경로만 전달한다.

### 라이선스와 공급망

- 7-Zip 공식 소스·바이너리만 사용하고 버전과 SHA-256을 고정한다.
- 7-Zip LGPL 및 포함 코덱 고지를 설치 파일의 `licenses`에 유지한다.
- 브리지 소스는 저장소에 포함하고 CI에서 MSVC `/O2 /GL` x64 release로 빌드한다.
- RAR 코드는 이번 브리지 기능에서 사용하지 않는다.
- `7z.dll` 바이너리는 저장소에 넣지 않고 현재 `fetch_tools.ps1` 방식대로 CI/빌드 시 공식 배포본에서 내려받아 SHA-256을 검증한다.
- 최소 지원 환경은 Windows 10 1809 x64이며 브리지는 MSVC 런타임을 `/MT`로 정적 연결한다.

### Python 경계

- 새 `archive_accel.py`가 DLL 로드, 기능 감지, 요청·응답 구조체, 오류 변환을 담당한다.
- `zipwriter.py`, `ziplib.py`, `formats.py`는 `can_accelerate()`가 참인 작업에만 네이티브 경로를 선택한다.
- 네이티브 함수는 긴 작업 동안 GIL을 점유하지 않으며, 취소 플래그는 원자적 정수로 전달한다.
- 진행률은 네이티브에서 누적 바이트만 갱신하고 Python은 최대 초당 10회 읽어 UI에 전달한다.

## 작업별 동작

### ZIP 압축

- 평문 Store/Deflate 신규 압축만 1차 가속 대상으로 한다.
- 레벨과 스레드 수를 7-Zip 속성으로 전달한다.
- 입력은 Python에서 정규화한 `(실제 경로, 아카이브 이름, 크기, 수정 시각)` 목록이다.
- 임시 ZIP을 완성하고 무결성 검증 후 기존 `finish_part` 규칙으로 게시한다.
- AES, 분할 ZIP, 기존 ZIP 편집은 기존 `zipwriter` 경로를 유지한다.
- 같은 ZIP에 지원·미지원 항목이 섞여 있으면 아카이브 전체를 기존 엔진으로 처리한다. 한 작업 안에서 두 해제 엔진을 혼합하지 않는다.
- 동일 레벨에서 결과 크기가 현재 yzip보다 `max(2%, 64 KiB)` 넘게 커지면 네이티브 ZIP 압축을 기본값으로 승격하지 않는다.

### ZIP 해제

- 중앙 디렉터리를 Python에서 먼저 읽어 암호화·메서드·경로 안전성을 판정한다.
- 안전한 대상과 임시 파일 경로를 브리지 callback에 제공한다.
- Store/Deflate만 네이티브로 해제하고 CRC·크기를 네이티브와 Python 양쪽 메타데이터로 검증한다.
- 모든 항목 성공 후에만 임시 파일을 최종 경로로 이동한다. 실패·취소 시 기존 파일은 보존한다.
- 충돌 모드와 선택 항목 해제는 기존 정책을 그대로 적용한다.

### 7z 해제

- 이번 완료 범위는 평문 LZMA/LZMA2다. 7z AES 네이티브 해제는 후속 단계이며 현재 py7zr 경로를 유지한다.
- coder/filter 구성이 네이티브 DLL에서 지원되면 전체 folder decode를 DLL에 맡긴다.
- Python은 결과 경로·충돌·트랜잭션 게시를 통제한다.
- DLL 오류, 비밀번호 callback 미지원, 특수 coder는 현재 `fast_plan`/py7zr 경로로 fallback한다.

## 안전성과 오류 처리

- 원본 아카이브는 읽기 전용이며 출력은 고유 `.part` 또는 전용 임시 폴더에 작성한다.
- 경로 탈출, 절대 경로, 장치 이름, 링크는 기존 `safe_target` 정책으로 차단한다.
- 선언 크기, 실제 출력 크기, 항목별·전체 출력 한도를 모두 검사한다.
- DLL 경계의 모든 HRESULT, 반환 코드, 포인터, 길이와 32/64비트 타입을 공식 헤더와 대조한다.
- 예외가 DLL 경계를 넘지 않게 하고 오류는 구조화된 코드로 반환한다.
- 취소·디스크 오류·CRC 오류·DLL 충돌을 주입해 원본과 기존 출력 보존을 검증한다.
- 가속기는 설정/환경 변수로 즉시 비활성화할 수 있다. 강제 종료·전원 종료를 DLL 실패로 오인할 수 있으므로 비정상 종료 표식 기반 자동 비활성화는 사용하지 않는다. 명시적인 DLL 로드·ABI·기능 감지 실패만 해당 실행에서 fallback한다.

## 단계적 적용

1. 벤치마크 하니스 고정 및 현재 기준선 재측정
2. DLL 로드·ABI·취소·진행률 브리지와 단위 테스트
3. ZIP 해제 가속 및 교차 무결성 테스트
4. 7z 해제 가속 및 coder별 fallback 테스트
5. ZIP 압축 가속 및 압축률·호환성 테스트
6. 전체 벤치마크에서 이득이 확인된 경로만 기본 활성화
7. GUI/CLI 회귀, 패키징, 라이선스, 악성 입력 검증

각 단계는 기능 플래그 뒤에서 독립적으로 되돌릴 수 있어야 한다.

- 단위: ABI, 버전, 오류 코드, 취소, 진행률 throttle, 크기 경계.
- 호환: yzip·반디집·7-Zip·Python이 만든 ZIP/7z를 상호 교차 압축·해제한다.
- 안전: zip-slip, 장치명, symlink/hardlink, 압축 폭탄, CRC 손상, 잘린 파일, 잘못된 헤더.
- 트랜잭션: 기존 출력이 있는 취소·쓰기 실패·게시 실패.

## 완료 조건

- 선택한 핵심 조건에서 목표 수치를 만족하거나, 미달 조건과 재현 가능한 병목 근거를 보고한다.
- 모든 교차 해시와 회귀 테스트가 통과한다.
- 가속기를 제거해도 기존 Python 경로가 정상 작동한다.
- 실행 파일을 외부 도구로 호출하지 않는다.
- 소스, 고정 버전, 라이선스, 벤치마크 원시 결과를 저장소 또는 배포 산출물에 남긴다.
